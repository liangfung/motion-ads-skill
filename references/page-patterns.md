# Page and Ad Patterns

Choose the output mode from purpose. An embedded ad card is a video with a thin interactive wrapper. A landing page is a designed document with its own structure and a complete narrative video. Ask when this distinction is unresolved; the scaffold's default is `card`.

## Video-card story options

These are compositional ideas, not mandatory scene counts. Brand/product and CTA artwork belong in the MP4; the HTML supplies playback and the real link.

| Pattern | Visual argument | Best fit |
|---------|-----------------|----------|
| Product detail | Recognizable object + hook → changed scale/crop with benefit labels → product/action resolution | One physical product with useful detail assets |
| Use and outcome | Real use-context image → supported feature or result explanation → next action | Lifestyle products and services with truthful source material |
| UI tour | Clear outcome → crisp screenshot details and short annotations → install/explore action | Apps or services with supplied real UI |
| Game-world invitation | Distinct world/character hook → varied screenshot beats with supported experience copy → store action | Steam games with key art/screenshots |
| Typographic campaign | Strong short statement → image/type relationship develops the argument → branded action | Brands with limited imagery and a distinctive voice |

Readability controls timing. Let annotation and copy settle before advancing. Change the visual relationship as the story develops rather than sliding identical cards over a looping image. A gallery-only render may support one of these stories; it does not replace the finished ad.

The starter's 9:16 frame, equal scene slots and fixed CTA region are editable. Respect supplied dimensions and update the HTML click region when CTA artwork moves.

## Landing-page recipes

| Recipe | Structure | Best fit |
|--------|-----------|----------|
| Product spotlight | Deliberate hero/video + headline/CTA on desktop, stacked on mobile; selected supported benefits and final CTA | One object, app or service |
| Editorial story | Oversized title, intentional video/photo crop, alternating detail/copy, quiet proof and CTA | Fashion, premium home, beauty |
| Product range | Clear promise, real variant/product cards, selected details and destination | Catalog with enough real assets/data |
| Game field guide | Immersive art and narrative video, premise/CTA, screenshot gallery and sourced play features | Steam game promotion |
| Evidence/feature tour | Narrative video, focused feature panels with screenshots, supported proof, CTA | UI products, appliances, strategy games |

Add sections only when they develop the argument. Missing reviews/offers/specs do not justify filler. A landing page should use desktop space deliberately and flow naturally on mobile. Its video still tells a complete ad story; duration follows that story rather than the page length.

## Useful interactions

| Interaction | Requirements and effect |
|-------------|-------------------------|
| Screenshot/image gallery | Real images; selected thumbnail changes large view/caption, with keyboard support and visible state |
| Benefit tabs | Supported features; update explanation and image, not only tab color |
| Variant selector | Real variant assets/data; update shown product, label and applicable CTA. Render matching video or keep it deliberately variant-neutral; never recolor to invent a variant |
| Before/after | Two real relevant states, clear labels and source/conditions; no fabricated results |
| Coupon reveal | Real supplied offer/code; show code and copy success/failure feedback without implying a random reward |

Use these when useful to the landing experience. A card needs no extra interaction beyond its action. For games, a gallery or feature tabs usually helps more than a fake mini-game.

## Category hints

| Category | Lead with | Useful detail | Avoid |
|----------|-----------|---------------|-------|
| Beauty/fashion | Material, shade, texture, real model/product | Real variants and qualified results | Fabricated medical/before-after claims |
| Electronics/home | Product silhouette and practical use | Exact specs, detail images, UI states | Invented performance or compatibility |
| Food/wellness | Real photography and supported benefit | Ingredients, provenance, supplied disclaimers | Unsupported health/safety claims |
| Apps/services | Recognizable UI plus clear outcome | Focused screenshot annotations | Fake downloads, ratings or working UI |
| Cozy/indie game | World, characters, atmosphere | Exploration/crafting only when sourced | Generic neon gaming skin |
| Action/arcade game | Distinct art, energy, readable title | Screenshot rhythm, real play modes | Calling animated stills gameplay |
| Horror/strategy game | Mood or systems with negative space/grid | Supported premise and features | Invented lore, awards or demo access |

## Copy and action

Headline = a supported benefit or distinctive experience; supporting copy = how/why it matters; CTA = the actual next action (“Shop the set,” “View on Steam,” “Wishlist on Steam”). Use “Download demo” only when it exists and the destination supports it.

Optional material includes a real brand mark, useful benefit labels, attributed review figure, supported offer/price and supplied legal text. No module is mandatory merely because a starter contains it. Landing pages can repeat the same primary CTA; cards keep the action region consistently available.

For clean player presentation, spacing and product-appropriate motion density, follow [design-guidelines.md](design-guidelines.md#clean-presentation-and-deliberate-spacing).
