# Question Guide

Research first; ask only when the answer changes the result, in the user's language. Use the host's clarification tool when available, following its supported schema, or ask directly in the conversation. Keep questions concise and offer a few distinct choices with a recommendation when useful.

Usually ask one compact round before the first draft, and a second if a real dependency remains. There is no fixed questionnaire to complete. Already clear choices need no reconfirmation. If the user explicitly delegates the format decision or asks for no follow-up questions, state sensible assumptions and proceed with supported content; do not invent missing facts.

## Resolve the intended output

An **embedded advertising video card** and a **standalone landing page** are different products. A card puts the persuasive story in the MP4, with a thin HTML player/click target. A landing page has a designed, usually scrollable HTML experience plus a complete narrative ad video.

When “ad page,” “interactive promo,” a product URL, or a reference leaves that distinction unclear, ask before building. Recommend a card for an embedded ad placement or an AppLovin-style video reference, and a landing page for a standalone visit with detailed exploration. Explain the visible outcome, not technical format names alone. The scaffold's default `card` is a convenience after the decision, not a reason to skip a material question. Explicitly delegated format choice can use that starting point.

## Decisions worth clarifying

| Area | Ask when | Useful choices |
|------|----------|----------------|
| Output/purpose | Embedding a video ad and creating a standalone page are both plausible | Embedded video card; designed landing page; named placement/spec |
| Product/story | Multiple products/variants, conflicting claims, or no usable assets | Use selected product; focus another variant; supply an original asset |
| Audience/action | Different audiences or CTAs imply different copy and evidence | Shop product; install app; wishlist on Steam; download demo (only if available) |
| Visual direction | Brand does not resolve a meaningful choice, or request is subjective | Two or three distinct genre/brand-aware directions, plus brand-match when useful |
| Motion source | User asks for gameplay/footage but only stills exist | Narrative screenshot/artwork animation; provide approved gameplay/trailer file; locate official source |
| Destination | No real URL or supplied link conflicts with requested action | Source product/store page; user-supplied campaign URL |
| Language | Source, audience, and user language imply different languages | Audience language; source language; requested localization |

Missing price, discount, ratings, or a testimonial is normally **not** a blocking question. Omit those elements and make the product argument using supported facts. A URL generally supplies the default CTA; retain affiliate/campaign parameters unless the user asks to change them.

## Ask with context

Show a compact summary of what was found: product/game, core promise or genre, 2–3 useful facts, chosen assets, and proposed CTA. Mention only uncertainties that affect design or truthfulness. Do not ask the user to verify every scraped field.

For an open-ended product URL, a useful round might combine:

- **Purpose/format**: “Do you want a video ad card to embed in another page, with benefits and a CTA inside the video, or a standalone landing page visitors can scroll through for more detail?”
- **Goal**: “I found [product] and suitable images. Should the primary action be buying this product or exploring the range?”
- **Style**: Offer visibly distinct brand-aware directions, such as quiet editorial detail, clean technical explanation, or bold retail rhythm.

Ask only the unresolved choices. Do not ask for an arbitrary duration merely because the template needs a number: propose timing from the story unless a placement has a real limit.

For a Steam game, distinguish a store visit, purchase, wishlist, and demo goal only when unresolved. Recommend direction from the actual world and audience: cozy illustrated field guide, immersive cinematic scene, retro arcade flyer, or restrained strategy dossier. Do not default every game to neon tech.

## After feedback

Apply specific edits directly. Ask a focused question only when feedback such as “more premium” has several materially different interpretations. Keep the working output and Remotion source; do not restart a questionnaire or regenerate everything for a small revision.
