# H5 composition and interaction patterns

Choose the amount of page content from the viewer's task. A compact embedded experience and a longer promotional page use the same Player H5 workflow; neither requires its own product mode. The Player supplies frame-driven animation, while ordinary HTML supplies natural reading flow, responsive sections and any useful controls.

## Visual argument

| Pattern | Information | Suitable evidence |
|---|---|---|
| Object detail | Recognizable subject → useful detail/callout → action | Exact product cutout/packshot and detail images |
| Use and context | Real use image → supported explanation → invitation | Honest lifestyle, serving or application material |
| Feature tour | Clear outcome → focused UI/part → compact takeaway | Real screenshots or product details |
| World invitation | Distinct art → environments/experiences → supported features → store action | Official artwork/screenshots; distinguish them from gameplay |
| Coordinated collection | Hero → grouped variants with readable labels → actual selection/action | Real variant assets, names and destinations |
| Typographic story | Short strong statement → meaningful image/type development → action | Distinctive copy grounded in evidence |

These are story functions, not scene-count rules. A stable stage can develop several regions in order; a longer story can change compositions while keeping theme constants. Add a section only when it develops the argument. Missing proof or specifications do not justify filler.

## Responsive reading

Preserve the subject and useful action at narrow sizes. Fixed-canvas type scales with Player size; if it becomes too small, shorten/recompose rather than trusting the source font size. Keep long paragraphs, product details and responsive grids in normal HTML when useful. Wider screens need deliberate whitespace and composition, not an accidentally stretched portrait stage. Check short phone heights and safe areas too.

## Useful interactions

| Interaction | Required behavior |
|---|---|
| Primary action | A real semantic link reaches the intended destination or actual page target; keyboard focus stays visible |
| Gallery | Real image selection updates the view/caption and exposes selected state |
| Variant choice | Real asset/copy/destination states agree; never recolor an image to invent a variant |
| Benefit tabs | Selecting updates useful explanation and corresponding evidence |
| Question/choice | Options produce a meaningful result or next step; do not fabricate personalized claims |
| Comparison | Two relevant real states, labels and necessary qualifiers; no invented outcomes |

An animation is not a playable game. Decorative controls that change nothing weaken trust. One real action may be sufficient; useful interaction is not measured by control count. Keep secondary choices quieter than the main action and preserve reduced-motion behavior.
